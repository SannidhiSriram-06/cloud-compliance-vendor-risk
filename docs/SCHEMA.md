## 1. Cloud Risk Register Schema (`risk_register.json` & `risk_register.csv`)

Generated by `lambda/risk_register_processor.py` and stored in the S3 Risk Register bucket.

### 1.1 Field Definitions

| Field Name | Type | Constraints / Format | Description & Purpose |
| :--- | :--- | :--- | :--- |
| `FindingID` | String | Unique identifier | Primary key. Derived from Security Hub Finding ARN or `config-<rule_name>-<resource_id>`. |
| `Source` | String | `"AWS Security Hub"` \| `"AWS Config"` | Authoritative AWS detection system originating the finding. |
| `Title` | String | Max 255 chars | Formal name of the compliance rule or benchmark evaluation that failed. |
| `Description` | String | Truncated to 250 chars | Summary of the specific violation and resource context. |
| `ResourceType` | String | e.g. `"AwsS3Bucket"`, `"AWS::EC2::Volume"` | AWS resource specification type for grouping and asset classification. |
| `ResourceID` | String | ARN, Name, or AWS ID | Unique resource identifier (e.g. bucket name, security group ID, volume ID). |
| `Severity` | String | `"CRITICAL"`, `"HIGH"`, `"MEDIUM"`, `"LOW"` | Normalized risk severity rating. |
| `RiskScore` | Integer | Scale 1 to 10 | Numerical risk rating derived from severity (`CRITICAL`: 10, `HIGH`: 8, `MEDIUM`: 5, `LOW`: 2). |
| `RemediationSLA_Days`| Integer | Days (1, 7, 30, 90) | Maximum target resolution window in days before audit SLA breach. |
| `ISO_27001_2022` | String | e.g. `"A.5.15 (Access Control)"` | Mapped control reference under ISO/IEC 27001:2022 Annex A. |
| `NIST_CSF` | String | e.g. `"PR.AC-3, PR.DS-1"` | Mapped subcategory controls under the NIST Cybersecurity Framework. |
| `CIS_AWS_Benchmark` | String | e.g. `"2.1.5 (Ensure S3 Bucket...)"` | Section number and title from CIS AWS Foundations Benchmark v1.4.0. |
| `RiskCategory` | String | Categorical string | Threat domain (e.g. `"Data Exposure"`, `"Network Exposure"`, `"Identity Governance"`). |
| `RemediationAction` | String | Actionable text | Prescriptive guidance for technical remediation. |
| `Status` | String | `"OPEN"`, `"IN_PROGRESS"`, `"RESOLVED"` | Lifecycle status in the risk register. Defaults to `"OPEN"`. |
| `LoggedTimestamp` | String | ISO 8601 UTC | Timestamp indicating when the finding was recorded. |
| `Environment` | String | e.g. `"sandbox"`, `"production"` | Deployment environment identifier. |

### 1.2 JSON Representation Example
```json
{
  "FindingID": "arn:aws:securityhub:us-east-1:123456789012:subscription/cis-aws-foundations-benchmark/v/1.4.0/2.1.5/finding/s3-public-read",
  "Source": "AWS Security Hub",
  "Title": "2.1.5 Ensure S3 Buckets Prohibit Public Read Access",
  "Description": "Bucket cloud-compliance-demo-public-demo has unrestricted public read access enabled via bucket policy.",
  "ResourceType": "AwsS3Bucket",
  "ResourceID": "arn:aws:s3:::cloud-compliance-demo-public-demo",
  "Severity": "HIGH",
  "RiskScore": 8,
  "RemediationSLA_Days": 7,
  "ISO_27001_2022": "A.5.15 (Access Control), A.8.24 (Use of Cryptography)",
  "NIST_CSF": "PR.AC-3 (Remote Access Management), PR.DS-1 (Data-at-Rest Protection)",
  "CIS_AWS_Benchmark": "2.1.5 (Ensure S3 Bucket Access is Restricted)",
  "RiskCategory": "Data Exposure / Confidentiality",
  "RemediationAction": "Apply S3 Public Access Block at account and bucket level. Remove open principal wildcard (*) from bucket policy.",
  "Status": "OPEN",
  "LoggedTimestamp": "2026-09-19T05:30:00Z",
  "Environment": "sandbox"
}
```

## 2. Third-Party Vendor Intake Questionnaire Schema (`vendor_intake_questionnaire.csv`)

Located in `vendor-risk/vendor_intake_questionnaire.csv`. Defines the evaluation criteria for incoming third-party vendors.

| Column Header | Data Type | Permitted Values / Format | Description |
| :--- | :--- | :--- | :--- |
| `Question_ID` | String | Format: `VND-<CAT>-##` | Unique question code (e.g. `VND-DP-01`, `VND-AC-01`). |
| `Category` | String | 6 Categories | Evaluation domain: `Data Protection`, `Access & Identity`, `Incident Response`, `Cloud Operations`, `Compliance & Governance`, `Resilience & DR`. |
| `Question` | String | Text | The security question posed to the vendor. |
| `Weight` | Integer | 1 to 5 | Criticality weighting factor (5 = Critical requirement, 1 = Informational). |
| `Required_Standard` | String | Text | Source regulatory standard (SOC 2, ISO 27001, NIST CSF, GDPR). |
| `Evaluation_Criteria`| String | Text | Criteria defining acceptable proof or deficiency triggers. |

## 4. Ingested Event Payload Structures

### 4.1 AWS Security Hub ASFF Event (EventBridge Detail)
```json
{
  "version": "0",
  "source": "aws.securityhub",
  "detail-type": "Security Hub Findings - Imported",
  "detail": {
    "findings": [
      {
        "Id": "arn:aws:securityhub:us-east-1:123456789012:subscription/cis-aws-foundations-benchmark/v/1.4.0/2.1.5/finding/xyz",
        "Title": "2.1.5 Ensure that S3 Buckets are configured with 'Block Public Access'",
        "Description": "Bucket public access block is disabled.",
        "Severity": { "Label": "HIGH" },
        "Compliance": { "Status": "FAILED" },
        "Resources": [
          { "Type": "AwsS3Bucket", "Id": "arn:aws:s3:::cloud-compliance-demo-public-demo" }
        ]
      }
    ]
  }
}
```

### 4.2 AWS Config Rule Compliance Event (EventBridge Detail)
```json
{
  "version": "0",

  "detail-type": "Config Rules Compliance Change",
  "detail": {

        "evaluationResultQualifier": {

          "resourceId": "vol-0123456789abcdef0"
        }
      },
      "resultRecordedTime": "2026-09-19T05:30:00Z"
    }
  }
}
```
